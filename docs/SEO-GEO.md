# SEO/GEO: реализация и обслуживание ALTWEB FACTORY

## Источник и архитектура

Проект восстановлен из самого свежего доступного снимка приложения Vercel `dpl_HKYyaQ1DELqGj5Ju4YaWCbrCiNuq`. Все 121 оригинальный файл проверены по SHA1 в `recovery-manifest.json`. При восстановлении временный preview изменял только сборочные настройки; оригинальный vercel.json получен отдельно и тоже сверён по SHA1. Исходники не восстанавливались из минифицированного JavaScript. Исходного GitHub-репозитория не существовало по данным владельца.

GitHub-интеграция вернула 403 на создание нового репозитория и переименование. Использован уже подключённый пустой репозиторий `altairtt60-ui/-`. В нём не было чужого кода или истории. Репозиторий изначально публичный; приватные ключи восстановления, временные архивы и файлы окружения в него не входят. Новый проект GitHub с желаемым именем владелец может создать/переименовать позднее; это не влияет на работу сайта.

Сохранены Vite, TypeScript и Phaser, все комнаты, NPC, SVG-ассеты, маршруты и игровые механики. Информационные страницы генерируются при `npm run build`, без отдельного сервера рендеринга. `scripts/generate-site.mjs` берёт контент из `src/content/site.ts`, существующих услуг `commerce.ts` и портфолио `projects.ts`. Тексты и JSON-LD строятся из одного источника.

Главная сохраняет полноэкранную фабрику. Под ней находится обычный видимый раздел со ссылками на услуги, работы и контакты. Ссылка с клавиатуры пропускает игру. Без JavaScript нерабочий игровой контейнер скрывается, а те же тексты остаются доступными. Скрытой версии текста только для роботов нет. Информационные страницы не загружают Phaser. При чтении текста под фабрикой симуляция приостанавливается и ввод освобождается.

У каждой страницы уникальные title/description, абсолютный canonical, Open Graph и один H1. Добавлены Organization, WebSite, WebPage, Service, BreadcrumbList и FAQPage там, где есть соответствующий видимый контент. Нет выдуманных адресов, рейтингов, отзывов, фиксированных цен и клиентских результатов. Разметка FAQ не означает права на расширенный сниппет Google.

`sitemap.xml` содержит 11 канонических страниц: шесть основных, четыре страницы разных задач и қазақша `/kk`. Lastmod не выдумывается при каждой сборке. `robots.txt` сохранил исходную политику `User-agent: * / Allow: /`, добавлена ссылка на sitemap. Googlebot, Bingbot, OAI-SearchBot и PerplexityBot не блокируются. Политика обучения моделей не менялась: общий Allow относится и к ним, отдельные правила GPTBot/CCBot не добавлялись.

Для неизвестных URL используется настоящий HTTP 404 с полезной страницей ошибки; catch-all rewrite на главную не добавлен. Vercel cleanUrls и trailingSlash приводят адреса к виду без `.html` и завершающего `/` (кроме главной). Известный альтернативный production alias перенаправляется на основной домен. Preview-адреса не перенаправляются, чтобы их можно было проверять.

Существующие заголовки CSP, HSTS и другие защитные заголовки сохранены. JSON-LD — неисполняемый блок данных; inline исполняемые скрипты ради него не разрешены.

Внешние проекты перепроверены по HTTP. 14 адресов доступны из проверочной среды, два chatgpt.site вернули 403. Последние больше не помечены как доступные; карточки и сохранённые изображения сохранены. Ссылка Dans Le Garage ведёт на собственный концепт Vercel, а не на официальный сайт бизнеса. Демо, концепты и учебные проекты не выдаются за клиентские заказы.

Instagram @altweb.design присутствовал в исходной конфигурации и на существующем сайте; публичный профиль с совпадающим handle открывается. Именно этот существующий канал используется в контенте и sameAs. Телефон и почта не придуманы.

`llms.txt` не добавлен: стандартные HTML, ссылки, sitemap и корректные статусы решают основные задачи обнаружения. Нет обещания рекомендаций AI или подтверждения включения в индекс.

## Сборка и проверки

Node.js 24:

```sh
npm ci
npm run build
npm test
```

Для Playwright нужен Chromium: `npx playwright install chromium` либо `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. На этой машине использован установленный `/usr/bin/chromium`. GitHub Actions настроен на Ubuntu 24.04 с установкой браузера и полным набором проверок. Исторические тесты и offline-скрипты отсутствовали в снимке; неработающие ссылки на них убраны из package.json. Это не заявление о восстановлении прежнего тестового покрытия или offline-сборки.

`npm run dev` запускает редактирование игровой части Vite. Полные статические страницы проверяются после сборки через `npm run preview`, локальный сервер со статусами 200/308/404 и сохранёнными заголовками безопасности. Этот сервер служит локальной проверке; опубликованные статусы нужно перепроверять в Vercel.

`test:seo`: HTML без JavaScript, metadata, JSON-LD, sitemap, robots, внутренние ссылки, мобильное переполнение, redirects, 404 и ответы с поисковыми User-Agent. Подмена User-Agent не проверяет доступ с реальных IP поисковых роботов и не подтверждает индексацию.

`test:browser`: шесть комнат на desktop/mobile, правильные панели, 17 NPC, конструктор, все три игры, неправильное соединение и успешная сборка, клавиатурное прохождение дизайн-пазла, повтор, сохранение результата после reload, подготовка заявки без отправки, перемещение и пауза при чтении.

`test:portfolio`: все 16 карточек и статусов, загрузка превью и совпадение фактических размеров, 14 подтверждённых адресов, правильный URL концепта, мобильный интерфейс и прямой переход к форме.

Ни HTTP 200, ни тесты не подтверждают коммерческий заказ, согласие клиента или бизнес-результаты внешних примеров. Лабораторные Lighthouse-замеры не являются полевыми Core Web Vitals; INP реальных пользователей требует отдельного измерения.

## Что подключает владелец

1. В Google Search Console добавить ресурс `https://altweb-factory.vercel.app/` с префиксом URL. Получить реальный HTML-файл или meta-тег подтверждения и добавить его в проект, затем пройти проверку. Для будущего собственного домена можно использовать DNS-ресурс. Не добавлять случайные verification-коды.
2. В Bing Webmaster Tools импортировать подтверждённый ресурс из Search Console либо получить собственный файл/тег подтверждения. После публикации отправить `https://altweb-factory.vercel.app/sitemap.xml` в оба сервиса.
3. Проверить главную и пять новых URL в инструментах проверки URL, проследить причины исключения и дату обхода. Доступность в этой сессии не означает, что URL уже проиндексирован.
4. Выбрать аналитику и политику согласия/приватности. Трекеры и идентификаторы без данных владельца не включены. При смене домена изменить `site.origin`, canonical, redirect и ресурсы вебмастеров вместе, затем пересобрать сайт.
5. При необходимости удалить два временных технических preview восстановления в панели Vercel: `dpl_69sQsfVuuySDweTx9p1zFhEeCAbr` и `dpl_8UcpgU9GPKGeBwnSxmZw3oXwTe1E`. Первый содержит только код шифрования с открытым ключом, второй — зашифрованный архив. Закрытый ключ не опубликован и не входит в GitHub.

### События и атрибуция

`public/site-events.js` не подключает сторонние трекеры и не записывает cookies/данные формы. Для подключения выбранной аналитики доступны DOM-события `altweb:engagement`:

- `brief_prepared` — текст заявки подготовлен локально, это не отправленная заявка;
- `contact_channel_opened`, channel `instagram` — клик по ссылке профиля, это не подтверждённое обращение.

Подключённый обработчик аналитики может слушать эти события; не передавать название бизнеса, текст заявки и другие значения полей. Реальные обращения считаются отдельно по фактически полученным сообщениям. Проверять referrer/UTM средствами выбранной аналитики; полезные источники — chatgpt.com, perplexity.ai, copilot.microsoft.com и gemini.google.com. Многие AI-переходы не передают referrer: полнота такой атрибуции ограничена.

На информационных страницах отсутствует игровой движок. Phaser оставлен в отдельном лениво загружаемом чанке (~355 КБ gzip). Предупреждение Vite о большом чанке сохраняется: движок нужен для существующей фабрики и не удалён ради формального размера. Превью WebP сохраняют настоящие размеры; первые два изображения портфолио загружаются сразу, первое имеет высокий приоритет, остальные — отложенно.

Расширение охвата запросов и языковой версии описано в [QUERY-COVERAGE.md](QUERY-COVERAGE.md). Лабораторные цифры выше относятся к предыдущей SEO-версии; они не выдаются за новый замер после расширения контента.
